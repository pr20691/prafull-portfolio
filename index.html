PrafullTalks — Automated Publishing System

Self-initiated, designed, built, and maintained end-to-end.

Self-Initiated Runs Daily · Unattended OAuth 2.0 · CI/CD

A fully automated content pipeline — no manual intervention

A self-built system that writes, validates, and publishes articles to this blog every day with no manual intervention. It integrates multiple third-party APIs, manages OAuth 2.0 authentication end-to-end, and runs on a scheduled CI/CD pipeline.

  • AI content generation: integrated the Anthropic Claude API with structured, multi-step prompting and automatic model fallback.
  • Publishing automation: integrated the Google Blogger API — OAuth 2.0 with full refresh-token lifecycle management — to publish content programmatically.
  • Self-healing internal linking: fetches live post data from the API to generate and verify working internal links, and automatically re-queues content if a linked post is later removed.
  • CI/CD: scheduled and monitored via GitHub Actions, with automatic failure alerts, dry-run testing modes, and validation checks before anything goes live.
  • SEO tooling: built diagnostic and bulk-repair scripts — including an automated internal-link auditor — to keep the live site healthy at scale.

Built independently — including debugging real production issues such as OAuth token expiry, third-party API breaking changes, and data-consistency bugs across a multi-service pipeline.

ASUR migration — architecture

A genuinely sequential pipeline: legacy retail data moves through Oracle SOA Suite and custom transformation logic before it ever reaches a downstream system.

Legacy Data → Structured Retail Output

Oracle SOA Suite · Core Java
STEP 01

Legacy Source

Client data extracted directly from legacy Oracle source databases.

STEP 02

Oracle SOA Suite

SOA composites with embedded Java drive the extraction and orchestration.

STEP 03

Transformation Logic

Custom-built transformation logic reshapes data inside the SOA composite.

STEP 04

Business Rules

Business and data-processing rules validate the transformed records.

STEP 05

MNT Output Files

Structured MNT files are generated as the pipeline's deliverable format.

STEP 06

Retail Systems

Output feeds downstream retail systems as part of the migration.
